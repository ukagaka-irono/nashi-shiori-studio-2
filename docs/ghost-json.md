# ghost.json の仕様

なし栞（`nashi.dll`）は、自分と同じフォルダにある **`ghost.json`** を読んで動きます
（`nashi.json` でも可）。エディタを使わず手で書いても構いません。

文字コードは **UTF-8**（BOM あり／なしどちらでも可）。Shift_JIS で書かれていた場合も
自動的に読み替えます。`//` と `/* */` のコメントも読み飛ばします。

## 全体の形

```jsonc
{
  "format": "nashi/1",

  "meta": {
    "name": "なしちゃん",          // ゴースト名
    "sakuraName": "なしちゃん",     // 本体の名前
    "keroName": "つぶ",            // 相方の名前
    "craftman": "作者名",
    "craftmanUrl": "",
    "homeUrl": "",                 // ネットワーク更新のありか（descript.txt の homeurl）
    "folder": "nashichan",         // 書き出すフォルダの名前（無ければ name。はじめて書き出したときに入る）
    "version": "1.0.0"
  },

  "settings": {
    "randomTalkEnabled": true,     // 自動でしゃべるか
    "randomTalkInterval": 180,     // 何秒ごとにしゃべるか（0 でしゃべらない）
    "noRepeatCount": 0,            // 直近いくつのトークを候補から外すか（0 でおまかせ）
    "autoWait": true               // 句読点のあとに少し間を置くか（無ければ置かない）
  },

  "variables": [                   // 変数の初期値
    { "name": "好感度", "value": 0 }
  ],

  "scripts": [ /* 下記 */ ]
}
```

`meta` と `settings` は省略しても既定値で動きます。

## scripts

`scripts` は「帽子ブロック 1 つぶんのかたまり」の配列です。

```jsonc
// イベントに反応する
{ "id": "s1", "kind": "event", "event": "OnBoot", "weight": 1, "blocks": [ … ] }

// ランダムトーク
{ "id": "t1", "kind": "talk", "name": "ひとりごと", "weight": 2, "blocks": [ … ] }

// 名前で呼ばれる（選択肢の行き先、call ブロック）
{ "id": "f1", "kind": "function", "name": "なでられた", "blocks": [ … ] }

// さくらの頭をなでられたときだけ動く
{ "id": "s2", "kind": "event", "event": "OnNadeNade",
  "filter": { "area": "Head", "who": 0 }, "blocks": [ … ] }

// 5 秒ごとに動く（定常ループ）
{ "id": "s3", "kind": "event", "event": "OnSecondChange", "everySec": 5, "blocks": [ … ] }

// ほかのゴーストに「こんにちは」と話しかけられたときだけ動く
{ "id": "s4", "kind": "event", "event": "OnCommunicate",
  "filter": { "contains": "こんにちは" }, "blocks": [ … ] }
```

| キー | 意味 |
|---|---|
| `id` | 任意の識別子。ランダムトークの重複回避と、`call` の代替キーに使われます |
| `kind` | `event` / `talk` / `function`。それ以外（つながっていない `loose`、付箋の `note` など）は無視されます。書き出す ghost.json には入りません |
| `event` | `kind: "event"` のときのイベント名 |
| `name` | `talk` / `function` の名前。`call` や選択肢の行き先で使います |
| `weight` | えらばれやすさ（既定 1）。同じイベントが複数あるとき、重み付きで抽選します |
| `everySec` | `OnSecondChange` を何秒ごとに動かすか（省略＝毎秒）。SSP は毎秒送ってくるので、栞側で間引きます |
| `filter` | イベントのしぼり込み。マウス系は `area`（当たり判定名 `Head` / `Face` / `Bust` / `Skirt` / `Hand`）と `who`（`0`＝本体・`1`＝相方）。`OnCommunicate` は `from`（相手の名前）と `contains`（言われたことにふくまれる言葉）で、どちらも**ふくんでいれば一致**。省略した項目は「どこでも／だれでも／なんでも」 |
| `disabled` | `true` にすると無効化されます |
| `x` / `y` | エディタ上の位置。栞は無視します |

`blocks` の中身は [ブロック一覧](blocks.md) を参照してください。

## 動きのきまり

* **イベントの抽選** — 同じ `event` のスクリプトが複数あるときは重み付きで 1 つ選びます。
  直前に選んだものは候補から外すので、同じ反応が 2 回続きません。
  選んだものが何も出力しなかった場合は、別のものを最大 4 回まで試します。
* **ランダムトーク** — `OnSecondChange` を数え、`randomTalkInterval` 秒たったら
  `kind: "talk"` から重み付きで 1 つ選んで再生します。
  **直近に出したものは候補から外します**（外す数は `noRepeatCount`。0 のときは
  トーク数の半分・最大 8）。外しすぎて候補が無くなるときは、古いほうから戻します。
  出した順番は `nashi_save.json` に残るので、起動しなおした直後も繰り返しません。
  SSP が「いましゃべってはいけない」状態（`Reference3` が `1` 以外）のときは待ちます。
  何かをしゃべると、タイマーはリセットされます。
* **くりかえしの間隔** — `everySec` があるスクリプトは、起動してからの秒数がその倍数の
  ときだけ動きます。毎秒まるごと動かすとそれだけで重くなるので、
  「◯秒ごと」を宣言してもらう形にしています。
* **しぼり込み** — `filter` があるスクリプトは、その条件に合ったときだけ候補になります
  （マウス系は `Reference4`＝当たった場所と `Reference3`＝相手、`OnCommunicate` は
  `Reference0`＝相手の名前と `Reference1`＝言われたこと）。
  一致するものが 1 つも無いときは既定の反応が返ります。
* **細かい条件が優先** — 同じイベントに `filter` 付きと `filter` 無しの両方があるときは、
  **条件を書いたほうだけ**が候補になります（「『こんにちは』と話しかけられたとき」は
  「話しかけられたとき」より先）。条件付きが複数あるときは、その中で重み付き抽選です。
* **ゴースト間通信** — `OnCommunicate` は `Reference0`＝相手の名前
  （SSP の通信ボックスからなら `user`）、`Reference1`＝言われたこと、です。
  こちらから話しかけるときは `communicate` ブロックを使います。栞は応答に
  `Reference0: 相手の名前` を付け、SSP がそれを相手の `OnCommunicate` として届けます。
  いっしょに `Age`（やりとりの世代数。初回 0、返すたびに +1）も付けるので、
  SSP 側でも長すぎる会話を止められます。
  栞自身も、話しかけ合いが 8 往復続いたら、しゃべるだけにして通信を打ち切ります
  （ゴースト同士が延々と会話し続けるのを防ぐため）。相手が付けてきた `Age` も数に入れ、
  1 分だまっていたら別の会話として数えなおします。
* **なでなで** — `OnMouseMove` が同じ場所の上で 20 回続くと、栞が **`OnNadeNade`** という
  イベントを自分で作って実行します（1.5 秒あくか、場所が変わるとリセット）。反応したあと 5 秒は続けて反応せず、
  しゃべっている途中（`Status: talking`）にも割りこみません。
  SSP がこの名前のイベントを送ってくるわけではありません。当たり判定の外は数えません。
* **選択肢** — `\q[表示,ID]` の ID と同じ `name`（または `id`）を持つ
  `function` / `talk` が `OnChoiceSelect` で実行されます。
  ただし、**栞が自分で出した選択肢・リンク（`\_a[ID]`）の ID だけ**です。
  入力ボックスの答え（`OnUserInput` の `nashi:変数名`）も、栞が開いた箱のぶんを 1 回だけ受け取ります。
  SSTP を送れるほかのプログラムが、同じイベントを作ってトークを動かしたり
  変数を書きかえたりできないようにするためです。
* **ネットワークの向こうから** — `SecurityLevel: external`（ほかのコンピュータから SSTP で
  届いたもの）には反応しません。
* **外から来た文字** — Reference などの値は、1 つ 32KB で切り、壊れた UTF-8 を `?` に直してから使います。
* **終了** — `OnClose` / `OnCloseAll` の応答には `\-` が必ず付きます
  （書き忘れてもゴーストが終了できなくなりません）。
* **ほかのゴーストへ切りかわるとき** — `OnGhostChanging` が無ければ、`OnClose` のセリフを
  `\-` をはずして使います（それも無ければ「またね。」）。`\-` を付けると、切りかえが止まってしまうためです。
* **自動の間** — `settings.autoWait` が `true` のとき、「しゃべる」「話しかける」ブロックの文の
  `、`・`，` のあとに `\_w[100]`、`。`・`！`・`？`・`…` などのあとに `\_w[300]` を足します。
  句読点が続くときは最後に 1 回だけ、すぐあとの閉じかっこ（`」』）】〕`）は間の前に置き、
  セリフのいちばん終わりには足しません。
  エディタで新しく作るゴーストでは入、これまでのゴーストは書いてないので切です。
* **書いていないダブルクリック** — ダブルクリック（`OnMouseDoubleClick`）を 1 つも書いていない
  ゴーストで、トークがあるときは、「なにか話して」「話す多さを変える」「なんでもない」の
  メニューを出します（「話す多さを変える」は `randomTalkEnabled` が切のときは出しません）。話す多さは 1 分ごと・設定どおり・10 分ごと・しばらく静かに、から選べ、
  保存データの `@talkInterval` に入ります（`randomTalkInterval` より先に使います。「いつもどおり」は `-1` で、
  設定の間隔にしたがいます。`randomTalkEnabled` が切なら、選んだ多さにかかわらず話しません）。
  メニューの行き先（`nashi.menu.…`）も、栞が出したものだけ受け付けます。
* **`\e` の補完** — 出力の末尾に `\e` も `\-` もない場合、`\e` を足します。
* **保存** — 変数は `nashi_save.json` に保存されます（終了時・2 分ごと）。
  となりに `nashi_save.json.tmp` を書いてから差しかえるので、途中で落ちても前の中身が残ります。
  起動してはじめて保存するときに、前の回の中身を `nashi_save.bak.json` に控えておきます。
  `nashi_save.json` がこわれている・大きすぎるときは、消さずに `nashi_save.broken-日時.json` へよけて、
  控えから読みなおします（控えも無ければ初めから）。ほかのプログラムが開いていて読めないだけのときは、
  よけたりせず、その回は保存しません（無事な本体を、読めていない値で上書きしないため）。
  はじめて起動した日（`firstBoot`）・さいごに起動した日（`lastBoot`）・さいごに保存した日（`lastSeen`）も入っていて、
  「何日ぶりか」「出会ってから何日か」の情報ブロックに使います。
  保存された値はプロジェクトの初期値より優先されます。
  やり直したいときは `nashi_save.json` と `nashi_save.bak.json` を消してください（エディタの「ゴーストの記憶を消す」は両方消します）。
* **自動読み直し** — `ghost.json` の更新を 3 秒おきに見ていて、
  変わっていれば SSP を止めずに読み直します。
  そのとき、新しく増えた変数だけが初期値付きで追加されます。

## ブロックがないときの既定動作

対応するスクリプトが 1 つもないイベントには、控えめな既定の応答を返します。

| イベント | 既定の応答 |
|---|---|
| `OnFirstBoot` | 「はじめまして。…です。よろしくね。」 |
| `OnBoot` | 「おかえりなさい。」 |
| `OnClose` / `OnCloseAll` | 「またね。」＋`\-` |
| `OnMouseDoubleClick` | 「なに？」など 3 種からランダム（トークがあれば、そのあとにメニュー） |
| `OnGhostChanging` | `OnClose` のセリフから `\-` をはずしたもの（無ければ「またね。」） |
| その他 | 応答なし（204 No Content） |

`ghost.json` が読めなかったときは、起動時にその旨と、**何行目の何文字目**がおかしいかをしゃべります
（例:「ghost.json の 4 行目 3 文字目: 「,」か「}」が来るはずのところに、ちがうものがあります」）。

## デバッグ

**SSP の開発者ツールへの知らせ** — まちがいに気づいたら、そのときの応答に
`ErrorLevel` / `ErrorDescription` を付けて SSP に渡します。SSP はエラーログに残し、通知領域にエラーのアイコンを出します。
知らせるのは、作者が直せるものです。

| 内容 | レベル |
|---|---|
| `ghost.json` が読めない（何行目の何文字目か） | `error` |
| 書きかえた `ghost.json` が読めず、前の中身のまま動いている | `warning` |
| 「よぶ」「◯秒後によぶ」の名前のトークが無い・名前が空・よんでいる途中のものをまたよんだ・16 段より深い | `warning` |
| 「◯の間くりかえす」が 5000 回で終わらない・「◯回くりかえす」が 5000 回をこえる・ブロックを 40000 回動かしても終わらない・入れ子が 48 段より深い | `warning` |
| SAORI が読めない・呼べない（待たずに呼んだものは、答えを受けとったときの応答で） | `warning` |
| 保存データが読めない・よけた・開けない（ほかのプログラムが開いているなど、使う人のパソコンのぐあい） | `notice` |
| 保存データを控え（`nashi_save.bak.json`）から読んだ | `info` |

イベントの中で起きたものには、頭にイベントの名前が付きます（例: `OnMouseDoubleClick: 「あいさつ」をよぼうとしましたが…`）。
同じ知らせは、起動しているあいだ 1 回だけです（「ずっとくりかえす」で毎秒起きても、エラーログを埋めません）。
`ghost.json` を読みなおすと忘れるので、直したつもりでまた起きれば、また知らせます。1 回の応答では 8 つまでです。

`nashi.dll` と同じフォルダに空の **`nashi_debug.txt`** を作っておくと、
読み込み結果や再読み込みのログと、上の知らせがそこに追記されます。
